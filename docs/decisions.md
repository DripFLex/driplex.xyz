# Décisions techniques — V2

1. **Évolution en place** : conventions Astro/TypeScript strict, contenus Markdown et routes V1 conservés. Photography et Travel pointent vers `/photos/` et `/map/`. Home garde son organisation éditoriale ; seul Training reçoit un dashboard.
2. **Statique** : aucun adapter, API, backend, PostgreSQL, Docker, authentification ou nouvelle VM. Projet autonome, aucune modification du dépôt AthleteOS.
3. **Validation** : Zod valide le JSON à la compilation et distingue Running de Strength. Astro Content Collections valide le frontmatter Markdown. Le type TypeScript est inféré du schéma. Les helpers purs sont séparés pour ne pas envoyer Zod au navigateur.
4. **JavaScript ciblé** : seulement Training pour filtre/année/graphe/détail. DOM natif, pas de framework hydraté. Données insérées avec `textContent`, jamais comme HTML arbitraire. Le JSON démo est public par construction ; aucune donnée personnelle ne doit y être ajoutée sans considérer sa présence dans le build.
5. **Dates civiles UTC** : une journée vaut une date ISO, sans heure ni fuseau local. Le calendrier commence lundi, complète les semaines par des cases hors année sans activité et respecte les années bissextiles grégoriennes.
6. **Référence temporelle de démonstration** : `DEMO_TODAY` fixe le 29 octobre 2026, clairement indiqué. Les fonctions acceptent une autre date pour les tests. Les futures ne contribuent pas aux statistiques, au journal ou aux couleurs.
7. **Identité** : palette centralisée ; polices Latin auto-hébergées par Fontsource et SVG Lucide compilés via `@lucide/astro`. Ces dépendances répondent aux demandes, sans service distant au runtime. Aucun package graphique ou calendrier.
8. **Accessibilité** : lien d’évitement, navigation nommée, page active, tooltips au focus, labels mobiles, statuts de filtre annoncés. Flèches dans le calendrier, Entrée/Espace pour ouvrir un jour, alternative sélecteur date tactile, région défilante. Volume disponible en texte, pas seulement en couleur.
9. **Inspiration** : https://araujo.zip/ consulté pour la V1. Rythme éditorial et navigation simple conservés, identité DRIPLEX propre. Aucun texte, photo ou asset propriétaire repris.
10. **Git et revue** : dépôt local créé car la V1 n’était pas suivie. Le GitHub fourni était vide ; V1 poussée comme base de revue. Commits V2 séparés, PR pour revue humaine, aucune fusion ni publication du site.
